# CRM administrador Implementation Plan

**Goal:** Centralizar equipo, trabajos y pendientes en un panel administrativo real.
**Architecture:** Ampliar el almacén local y una API administrativa; shell compartido y páginas operativas que reutilizan usuarios, permisos y papelera.
**Tech Stack:** Next.js 15, React 19, TypeScript, node:test, CSS existente, sin nuevas dependencias.
**Spec:** docs/superpowers/specs/2026-10-25-crm-admin-design.md

## Constraints
- Solo administradores; conservar datos anteriores y permisos de archivos.
- Métricas calculadas, sin contenido ficticio ni nuevas cuentas de producción.
- Fechas de vencimiento interpretadas en America/La_Paz.
- No publicar, no confirmar cambios ajenos.

## Tasks
- [x] 1. Pruebas fallidas y backend: trabajos, pendientes, referencias de responsables y migración compatible. API /api/admin/crm.
- [x] 2. Formularios y listas de trabajos, tablero de pendientes, filtros y edición con estados de carga/error/vacío.
- [x] 3. Shell /admin, dashboard calculado, actividad y vista de roles; integrar navegación existente.
- [x] 4. Integración HTTP, navegador real, revisión independiente, lint/build y documentación de acceso.

## Review focus
- Lectores no acceden a CRM ni pueden forjar roles.
- Las actualizaciones conservan tareas académicas y demás datos del almacén.
- Responsables desactivados y trabajos inexistentes no generan referencias inválidas.
- El dashboard no mezcla tareas académicas con pendientes CRM ni cuenta cancelados como abiertos.
- Móvil permite ejecutar las acciones de administración sin desbordamiento de página.

## Progreso
Implementación completa con backend/UI delegados y revisión independiente. Se conserva el checkout con cambios previos, sin commits ni publicación.

- `node --test tests/*.test.cjs`: 38/38 pruebas correctas, incluyendo migración, autorización, trabajos/pendientes, referencias inactivas, métricas, API HTTP y regresiones previas.
- `npx next lint`: sin advertencias ni errores ESLint.
- `npx next build`: correcto, 21 páginas generadas y rutas CRM dinámicas.
- Navegador Edge real, datos temporales: login, dashboard vacío y con datos, crear trabajo, asociar responsable/fecha/prioridad, crear tarea vinculada, iniciar/completar/editar, atajos con query, roles, actividad filtrada y bloqueo a usuarios normales. Sin excepciones JS.
- Capturas revisadas a 1440, 768 y 390 px, temas claro y oscuro, sin desbordamiento horizontal de página. Archivos locales en tmp/crm-review.
- Corrección de revisión: conservar responsable histórico desactivado al actualizar un trabajo/pendiente; impedir asignaciones nuevas a cuentas desactivadas. Regresión reproducida y corregida.
- README actualizado con acceso y funciones. Trabajos y pendientes separados de las tareas académicas existentes; ninguna cuenta ni trabajo de ejemplo creados en datos reales.
- Ruling operativa: otra tarea recompila simultáneamente `.next`, reemplazando los archivos del servidor. Se admite `NEXT_DIST_DIR` opcional en next.config.ts y se usa `.next-crm` para aislar la ejecución del panel. La salida predeterminada sigue siendo `.next`; README e ignore actualizados.
